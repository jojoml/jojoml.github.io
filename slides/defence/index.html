[0:40] Any feed-forward neural network can be seen as a directed acyclic graph, which lets us describe it as a pair: the cell-type vector, X, and the adjacency matrix, A. The zeros and ones in A say whether one cell is wired to another, for example the second to the fifth, and the entries of X say which computation each cell performs.

Limitations

It does not see the topology: the structure is lost in the chain.

[0:50] Before GraphPNAS, previous work used an RNN as the controller. The RNN sequentializes the same directed acyclic graph into a chain: for each node, its connections and then its operation, predicted one by one.

▸ click So there are immediately two limitations. First, it completely ignores the topology, because the structure is lost in the chain. Second, with many nodes, the chain creates long-range dependencies that are hard for the model to pick up. Here, node 5 has to refer back to node 2.

GraphPNAS · Generator

Build the graph node by node, seeing the partial graph

\(p(G) = \prod_i\, p(\text{node}_i,\ \text{its edges} \mid \text{graph so far})\)

Edges: a mixture of \(K\) Bernoullis

\(\mathbb{P}\left(A_{i,:} \mid A_{i-1,:}, X_{i-1}, \cdots, A_{1,:}, X_{1}\right) = \sum_{k=1}^{K} \alpha_{k} \prod_{1 \le j < i} \theta_{k,i,j}^{A_{i,j}} \left(1-\theta_{k,i,j}\right)^{1-A_{i,j}}\)

Cell type: a categorical

\(\mathbb{P}\left(X_{i} \mid A_{i-1,:}, X_{i-1}, \cdots, A_{1,:}, X_{1}\right) = \text{Categorical}\left(\beta_{1}, \cdots, \beta_{D}\right)\)

[0:55] So instead, we treat the generation as an autoregressive process on the graph itself: the generator always sees the graph built so far. Let's say we start with a partial graph that is already generated.

▸ click We augment it with a new node, and all the possible edges to the earlier nodes,

▸ click encode the new graph with node and edge features,

▸ click and put all the features into a graph neural network, for message passing.

▸ click Then we model the edges as a mixture of Bernoulli distributions, and the node as a categorical distribution, where the parameters come from the output of the graph neural network.

▸ click And we sample from them, to get the new edges and the new node type. That finishes one round of graph generation.

[1:05] Our assumption about the implicit structure is that this motion can be decoupled.

▸ click First, the fine-grained grasp between the fingers and the object, in each frame.

▸ click Then the global motion: the paths of the wrist and the object in 3D space. And what connects the two is a latent: a grasp code, Z, for each frame.

▸ click The diffusion model generates the global motion together with Z, and each frame's grasp is decoded from its code, given the wrist and the object. Put together, they give the complete hand–object motion. So the structure we use is not the shape of the hand: it is how the motion splits, given the latent.

▸ click So three stages: we learn the grasp with a GraspVAE, the first stage; the global motion with a diffusion model, the second stage; and then generation, the third. Now each stage in turn.

▸ click A lookup is cheap: it gives the model extra capacity at very little compute, where rebuilding the meaning takes layers.

▸ click But the entry is chosen by the token alone, blind to its context: "bug" the insect and "bug" the software error read the same entry.

[0:50] Take the token "bug": in the first sentence it means an insect; in the second, a software bug. Previous methods index the memory by the token ID, like Value Embedding and STEM, or by a hash of the last few tokens, like Engram. Either way, both senses get the same key, so they read the same cell of the memory.

▸ click But what "bug" means depends on its context: the gardener and the plant make it an insect; delaying the release makes it a software bug. That is the implicit structure.

▸ click In ours, the token, through f, still picks a row of the memory: the same row for both.

▸ click But a router, g, reads the context, the hidden state, and picks which slots in that row to read: here, different slots for the two senses.

Mixture of Memory Embeddings · Method

We start with a vanilla transformer

Every other block is memory-augmented; the rest is a standard transformer

\(n_t = f(x_t)\)

The token picks its row of \(M\) memory slots

\(g_\theta(\mathbf{h}_t) \rightarrow (\mathcal{A}_{t,i},\, \alpha):\quad \mathcal{A}_{t,i} = \mathrm{TopK}\big(\mathbf{W}^{(i)}_g \mathbf{h}_t + \mathbf{b}^{(i)}_g,\ K\big)\)

A router reads the hidden state and selects the top-\(K\) slots for each value head \(i\)

\(\tilde{\mathbf{m}}_{t,i} = \sum_{a \in \mathcal{A}_{t,i}} \alpha^{(i)}_{t,a}\, \mathbf{m}_{n_t,a}\)

The selected slots are mixed into one memory vector

\(\tilde{\mathbf{v}}_{t,i} = \mathbf{v}_{t,i} + \gamma_{\theta,t,i}\, \tilde{\mathbf{m}}_{t,i}\)

A gate adds it to the attention values: routing chooses what to read, the gate how much

[1:10] More concretely, here is the architecture. We start with a vanilla transformer architecture.

▸ click Then memory-augmented blocks alternate with the regular transformer blocks.

▸ click In each memory block, first the token index selects its row of memory slots.

▸ click Then the router reads the hidden state and selects the top-K slots in that row.

▸ click The selected slots are mixed into one memory vector.

▸ click And a gate adds it to the attention values. That's how the memory is fused into the transformer. The hidden state comes from the causal attention of the previous layers, so it has seen all the previous context. That makes our router context-aware, while previous methods index the memory by the token alone.

[0:35] So to conclude. My thesis studied generative modeling of explicit and implicit structure, across a few different applications. When we care about explicit structure, we should capture it in the training recipe. And when the structure is implicit, we can make assumptions about it, and use them to design the model. In both cases, building the structure in pays off: our models learned more efficiently, generalized better, and became more interpretable

Future work

Does a designed structure still pay off at frontier scale?

In other words: where does the Bitter Lesson stand on this axis?

The Bitter Lesson: R. Sutton, 2019

[0:50] Looking ahead, one open question remain. Everything in this thesis sits at the small end of this scale: limited data, or at most 100 billion tokens.

▸ click Frontier models train on tens of trillions of tokens, far beyond what we can train. Does a designed structure still pay off there? We don't know yet.

▸ click In other words: the Bitter Lesson, from Rich Sutton, tells us that general methods that scale with computation eventually win over methods that build in what we know. So where does the bitter lesson stand on this axis? My best guess: the advantage of designing structure may diminish as data and compute scale, but it will still pay off. Under the same data and compute budget, modeling the structure will still be more efficient than not modeling it.
